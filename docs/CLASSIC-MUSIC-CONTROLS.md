# Classic Music collector controls

The original Async backend at `C:/projects/async-server-2-staging` stores layer controls from each layer token's IPFS metadata (`modules/EthScanner.js`, layer ingestion). Its `handleControlLeverUpdatedEvent` queues a rerender of the containing master when a layer changes. `models/Art.js` maps music stems to master audio-layout entries and extracts visual previews from the linked visual states. The backend states that masters themselves do not have controls; owning a master alone does not grant this interface permission to edit separately owned stems.

On 2026-11-07, read-only `tokenURI` and `getControlToken` calls recovered all 85 stem references across the 17 master records currently in the archive metadata inventory. This is an inventory count, not a claim that 17 distinct original commercial releases existed. 33 original stem metadata documents were retrievable. 52 additional archive layer records were reconstructed using the original master audio/visual layouts and the contract's min/max/current triplets. All recovered control ranges were checked against the chain; missing metadata was never silently treated as an original document or published under its CID. `src/data/music-control-provenance.json` distinguishes the two sources. Reconstructed records do not invent an artist attribution.

Betty's Notebook #1592 has four recovered original layer records, #1593–1596, each with a single state lever (0–2). Those same relative token IDs and lever 0 select both audio files and multiple visual layers. The Choir's original labels are Studio, Concert Hall, Directional. The original master metadata has no separate master-owner control.

The existing visual LayerControlDialog is now available under Music layers and from the player’s stem explorer. Preview shares the viewer's control override map, changing both the audio selection and linked composition. Selecting a new mix pauses playback; the listener presses Play. The dialog reads live settings on open, recognizes owner addresses regardless of case, clears stale ownership on wallet/layer changes, and submits only changed, in-range levers to `useControlToken` on the configured Ethereum chain. The user signs their own transaction. Confirmed writes apply the submitted preview values locally. Visitors and disconnected wallets can preview but cannot save through the GUI.

Remaining scope: permissioned/delegated controllers are supported by the original contract but this GUI currently exposes saves to token owners only. Original renderer-server mastering and automatic refresh in already-open viewers are separate restoration tasks. On-chain writes require a collector’s own wallet; no real transaction was submitted during verification.

Validation: control-state, bounds, ownership matching, original Betty labels, all 85 index records, music playback regressions, gallery/search regressions, TypeScript and browser preview checks. Original IPFS files and the working streaming transport are preserved.
